# 项目宪章与技术约束

> 状态：✅ 已确认（基于多轮讨论固化） · 最后更新：2026-11-26

## 1. 产品定位

**AI Panel Studio** 是一款「AI 圆桌讨论」本地 Web 应用：用户输入任意讨论话题并指定参会专家人数（默认 4 人），系统调用大模型动态生成一组主持人与专家嘉宾，展示每位嘉宾的姓名、职业、Title、立场与专属颜色标识；用户确认阵容后进入演播厅讨论模式，观看一场由 AI 驱动、实时推进的圆桌讨论。

**核心价值主张**：让任何人都能瞬间召集一支「虚拟智库」，围绕任意议题展开深度碰撞——主持人负责开场、追问、串联与收尾，专家之间自主「举手/抢答/补充/反驳」，讨论过程中持续生成共识与分歧，最终呈现一场沉浸式的 AI 圆桌实况。

## 2. 目标用户

| 人群 | 核心诉求 |
|---|---|
| 知识工作者 / 研究者 | 获得可录制、可回放的「虚拟专家访谈」素材 |
| 产品 / 决策人员 | 发现盲点、检验假设，提升决策质量 |
| 教育 / 内容创作者 | 结构化呈现复杂议题，追求沉浸感与叙事性 |

> 本期只做**通用版覆盖共性**，差异化能力（输入假设、叙事模式、导出）均列为非目标。

## 3. 核心闭环（本期范围）

输入话题 + 专家人数 → 生成主持人 + 专家阵容 → 用户确认 → 进入演播厅观看实时讨论 → 主持人自然语言总结。

## 4. 范围（做 / 不做）

### 4.1 做（In Scope）
- 首页：讨论列表（6 态分组）+ 发起新讨论 + 加入观察已有讨论
- 嘉宾生成：话题 + 人数（2–8，默认 4）→ 主持人 + 专家阵容（姓名/职业 Title/立场/颜色）
- 阵容确认：可编辑姓名/立场等文本字段 + 一键重新生成
- 演播厅：主持人开场/追问/串联/总结；专家自主发言（每次 1–2 句，不机械轮流）
- 专家状态小窗：待机/准备发言/发言中 + 公开思考摘要（隐藏真实 CoT）
- 实时共识/分歧提炼（观察员 Agent，每 5 条专家发言）
- 现场 Transcript（姓名 + Title + 色块区分，不显示内部事件）
- 主持人自然语言总结
- 回放：带时间轴、动画的沉浸式回放，动态重现整场过程
- 直接看结果：纯文本视图（transcript + 共识/分歧 + 总结）

### 4.2 不做（Out of Scope）
- 输入假设/立场（决策者差异化）
- 叙事模式（创作者差异化）
- 导出 / 存档（专门管理界面）
- 多用户、登录、身份、权限体系

## 5. 技术框架

| 层 | 选型 | 职责边界 |
|---|---|---|
| 工程 | npm workspaces monorepo（shared / server / web） | 前后端共享同一套契约 |
| 契约 | Zod | 一套 Schema = 类型推导 + 运行时校验 + LLM 输出校验 |
| 前端 | Vite + React + TypeScript + Tailwind | 纯界面渲染 + 状态展示 + SSE/REST 订阅；零 LLM、零密钥 |
| 后端 | Node + Express + TypeScript | 全部 LLM 调用、SSE 推送、Prisma 读写、讨论引擎 |
| 数据库 | SQLite + Prisma | schema + migration + seed（5 条含完整事件时间线） |
| 实时 | SSE（text/event-stream） | 按 discussionId 分频道、带 id 断线续传、心跳保活 |
| 单测 | Vitest | 嘉宾生成 / 发言调度 / 共识提炼 |
| E2E | Playwright | 全流程闭环 |

## 6. 技术约束（铁律）

- **密钥隔离**：LLM API Key 仅存后端环境变量，绝不暴露到浏览器端。
- **单机单人**：本地单机使用；「多讨论并行隔离」= 同一用户并发多场讨论的数据与通道隔离，非多人协作。
- **中文 UI + 响应式**：不依赖整页滚动，各区域自身容器内独立滚动；超宽屏 / 桌面 / 窄屏合理分区。
- **LLM 接入**：OpenAI 兼容协议，base URL 可配（DeepSeek / 通义 / Kimi / Ollama 可切换）。
- **双模型配置**：`LLM_MODEL_INTENT`（轻量意图）与 `LLM_MODEL_SPEECH`（正式发言）独立配置，MVP 可填同一模型。
- **Mock Provider**：`LLM_PROVIDER=mock` 提供确定性、零成本、零网络的输出，作为单测与 E2E 的前提。

## 7. 非功能约束（上限保护）

| 项 | 值 |
|---|---|
| 最大轮次 | 40 |
| 最大时长 | 15 分钟 |
| 最大 LLM 调用次数 | 200 |
| 同时运行讨论数 | ≤ 3 |
| LLM 全局并发 | ≤ 8（信号量） |

任一上限触达即强制进入 P4 总结收尾。
